### Android device headers (sent on all SAPI calls)
- User-Agent: `Dalvik/2.1.0 (Linux; U; Android 12; SM-A515F Build/SP1A.210812.016)`
  (Simulates Samsung Galaxy A51 running Android 12)
- X-Requested-With: `com.jazz.drive`
- X-deviceid: generated by `get_x_deviceid(msisdn)` → `android-raddhub-{last_10_digits_of_msisdn}`
  **Why this prefix:** `android-raddhub-` avoids kicking the user's real phone app session — Jazz treats it as a different device
- JSESSIONID cookie for session
- validation_key: dynamic header from OAuth/OTP flow

### Suspension protection patterns
- Proxy chaining for geo-sensitive calls (OTP, Login, Refresh) — Oracle IP is non-Pakistani, triggers MED-1011
- `_get_refresh_lock(account_id)` — per-account mutex to prevent concurrent refresh_token use (Jazz rotates token on each use; race = invalid_grant = account flag)
- `_REFRESH_COOLDOWN_S = 180` — 3-min cooldown between token refreshes
- SAPI backoff registry (_SAPI_BACKOFF) — 30-min backoff if OTP required; persisted to sapi_backoff.json
- Dual login candidates: tries "Android-Nested" and "Android-Flat" JSON structures

## APK research goal
Decompile `com.jazz.drive` APK with jadx. Install jadx:
```bash
sudo mkdir -p /opt/jadx
wget -q https://github.com/skylot/jadx/releases/download/v1.5.0/jadx-1.5.0.zip -O /tmp/jadx.zip
sudo unzip -q /tmp/jadx.zip -d /opt/jadx
sudo chmod +x /opt/jadx/bin/jadx
```

Key things to grep in decompiled source:
- Headers: `grep -r 'X-deviceid\|X-Requested\|User-Agent\|X-platform\|X-app\|X-version\|Accept-Language' ... --include='*.java'`
- Device ID generation: `grep -r 'deviceid\|ANDROID_ID\|getDeviceId\|generateId\|buildSerial' ...`
- Keepalive: `grep -r 'keepalive\|heartbeat\|ping\|timer\|AlarmManager\|WorkManager' ...`
- Chunk size / upload: `grep -r 'chunk\|chunkSize\|CHUNK\|boundary\|multipart' ...`
