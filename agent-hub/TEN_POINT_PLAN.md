## PHASE B — Database Performance
**Effort:** ~1 session | **Risk:** Low (isolated to local_db.dart and sync_service.dart)
**Goal:** Eliminate the N+1 catalog load, make sync atomic, add missing index, and move heavy work off the main thread.

### B1 — N+1 query in catalog load (most impactful fix in the app)
**File:** `raddflix_flutter/lib/providers/catalog_provider.dart` ~L182-185
**Finding:** `CatalogNotifier._loadFromDb` calls `LocalDb.getEpisodes(show.id)` inside a
loop, once per TV show. On a catalog of 200 shows, app startup fires 201 sequential DB
round-trips. Each call is `SELECT * FROM episodes WHERE title_id = ?`.
**Fix:** Add `LocalDb.getEpisodesForIds(List<int> showIds)` to local_db.dart:
```dart
Future<Map<int, List<Map<String,dynamic>>>> getEpisodesForIds(List<int> ids) async {
  final db = await database;
  final placeholders = ids.map((_) => '?').join(',');
  final rows = await db.rawQuery(
    'SELECT * FROM episodes WHERE title_id IN ($placeholders) ORDER BY title_id, season, episode',
    ids,
  );
  final result = <int, List<Map<String,dynamic>>>{};
  for (final row in rows) {
    final tid = row['title_id'] as int;
    result.putIfAbsent(tid, () => []).add(row);
  }
  return result;
}
```
Then in catalog_provider.dart call this once and pass the map to each show.
- [x] Add LocalDb.getEpisodesForIds() batched query
- [x] Update CatalogNotifier._loadFromDb to use batched query

### B2 — N+1 in `getTopFreeMovies` decode loop
**File:** `raddflix_flutter/lib/core/db/local_db.dart` ~L1191
**Finding:** A loop iterates rows and calls `_decodeUrl(row)` per item. `_decodeUrl` does
XOR + base64 decode inline in the loop body on the main thread for every item.
**Fix:** Either process decoding lazily (only when URL is actually needed for playback),
or batch-decode all URLs in one `compute()` call off the main thread.
- [x] Defer or batch _decodeUrl in getTopFreeMovies

### B3 — N+1 in `getPendingUsageBytes` loop
**File:** `raddflix_flutter/lib/core/db/local_db.dart` ~L1464
**Finding:** Loop calls individual DB lookups per item. Replace with a single
`SELECT SUM(size_bytes) FROM downloads WHERE status = 'pending'` query.
- [x] Replace getPendingUsageBytes loop with single SUM query

### B4 — Sync has no transaction: partial sync corrupts DB state
**File:** `raddflix_flutter/lib/core/db/sync_service.dart` ~L110-133
**Finding:** `_persistItems` iterates and `await`s `upsertTitle()` + `upsertEpisode()` for
each item individually. No `db.transaction()` wraps the batch. If the device loses power
or the app is killed at item 87/200, the DB has 87 new items and 113 old items with no way
to detect or recover the inconsistency.
**Fix:**
```dart
await db.transaction((txn) async {
  for (final item in items) {
    await txn.insert('titles', item.toMap(), conflictAlgorithm: ConflictAlgorithm.replace);
    for (final ep in item.episodes ?? []) {
      await txn.insert('episodes', ep.toMap(), conflictAlgorithm: ConflictAlgorithm.replace);
    }
  }
});
```
- [x] Wrap _persistItems in db.transaction() in sync_service.dart

### B5 — Missing index on `episodes(title_id)`
**File:** `raddflix_flutter/lib/core/db/local_db.dart` schema section
**Finding:** `getEpisodes(showId)` queries `WHERE title_id = ?`. The episodes table has no
explicit index on `title_id`. On a large local catalog, this is a full table scan every call.
**Fix:** Add to schema migration:
```sql
CREATE INDEX IF NOT EXISTS idx_episodes_title_id ON episodes(title_id);
CREATE INDEX IF NOT EXISTS idx_episodes_file_id ON episodes(file_id);
CREATE INDEX IF NOT EXISTS idx_watch_positions_file_id ON watch_positions(file_id);
```
Increment schema version and handle in `_migrate()`.
- [x] Add idx_episodes_title_id index
- [x] Add idx_episodes_file_id index
- [x] Add idx_watch_positions_file_id index

### B6 — `rebuildFtsIndex` runs on main isolate
**File:** `raddflix_flutter/lib/core/db/local_db.dart` `rebuildFtsIndex` method
**Finding:** The FTS5 index rebuild deletes and re-inserts every row in the FTS virtual table.
On a 500-item catalog this is a heavy operation running synchronously on the UI thread,
causing a visible freeze the first time search is opened after a full sync.
**Fix:** Move `rebuildFtsIndex()` call into `compute()` or `Isolate.run()`. Since SQLite
in-process isolates share the WAL file, the simplest safe approach is:
spawn an isolate that opens the same DB file, runs the rebuild, closes it, and signals done.
- [x] Move rebuildFtsIndex to background isolate

### B7 — Sync has no retry logic
**File:** `raddflix_flutter/lib/core/db/sync_service.dart`
**Finding:** `syncFull` and `syncDelta` have no retry on transient failure. A single
network timeout kills the entire sync. On Pakistani mobile networks (frequent handoff,
variable signal) this means catalog updates silently fail until the user manually reopens.
**Fix:** Add simple retry wrapper:
```dart
Future<T> _withRetry<T>(Future<T> Function() fn, {int attempts = 3}) async {
  for (int i = 0; i < attempts; i++) {
    try { return await fn(); }
    catch (e) {
      if (i == attempts - 1) rethrow;
      await Future.delayed(Duration(seconds: 2 * (i + 1)));
    }
  }
  throw StateError('unreachable');
}
```
- [x] Add retry wrapper to syncFull and syncDelta

### C2 — Debounce `_savePrefs` (60 call sites → 1 delayed write)
**File:** `raddflix_flutter/lib/screens/player_screen.dart` ~L1681
**Finding:** `_savePrefs()` writes to SharedPreferences synchronously on the main thread.
It is called from ~60 locations including inside `setState()` closures. SharedPreferences
I/O on the main thread is a known cause of dropped frames on mid-range Android devices.
**Fix:**
1. Add a debounce timer field: `Timer? _savePrefsDebouce;`
2. Replace `_savePrefs()` with `_scheduleSavePrefs()`:
```dart
void _scheduleSavePrefs() {
  _savePrefsDebounce?.cancel();
  _savePrefsDebounce = Timer(const Duration(milliseconds: 300), _savePrefs);
}
```
3. Add `_savePrefsDebounce?.cancel()` to `dispose()` before the existing timer cancellations.
4. Replace all call sites of `_savePrefs()` (except inside `dispose()`) with `_scheduleSavePrefs()`.
- [x] Add _scheduleSavePrefs() debounce wrapper in player_screen.dart
- [x] Replace all mid-session _savePrefs() calls with _scheduleSavePrefs()

- [x] Audit and remove confirmed dead state vars in player_screen.dart — RE-VERIFIED: `_currentFramedrop` (read/written in `_setSpeed`, gates a real seek-flush branch) and `_labDialogueOnly` (persisted to prefs, drives a real audio-pan filter; the second occurrence at ~L7476 is a *different* class's own field, not a stale duplicate) both have real, meaningful reads. ### C4 — Fix `_savePrefs` being called inside `dispose()` after debounce
**File:** `raddflix_flutter/lib/screens/player_screen.dart` dispose()
**Finding:** `dispose()` calls `_savePrefs()` directly to ensure final state is written
before the widget is destroyed. With the debounce in C2, `dispose()` must call `_savePrefs()`
directly (not `_scheduleSavePrefs()`) and must also cancel the debounce timer first.
This is explicitly called out to prevent C2 from breaking the dispose-time save.
**Fix:** In dispose(): `_savePrefsDebounce?.cancel(); await _savePrefs();`
(or call synchronously — SharedPreferences is fast when called once at dispose time).
- [x] Ensure dispose() calls _savePrefs() directly, not the debounced version

## PHASE E — Provider Architecture: God Provider Split
**Effort:** ~2 sessions | **Risk:** Medium (catalog_provider.dart is load-bearing)
**Goal:** Split CatalogNotifier's 6+ responsibilities into 3 focused providers.
This makes each piece testable, reduces rebuild scope, and isolates sync bugs.

### E1 — Extract `SyncNotifier` from CatalogNotifier
**File:** `raddflix_flutter/lib/providers/catalog_provider.dart`
**Finding:** CatalogNotifier responsibilities confirmed from code:
1. Load catalog from DB
2. Trigger and execute server sync (full + delta)
3. Schedule and run poster sync
4. Track continue-watching / recently-watched
5. Rebuild FTS index
6. Load recommendations in background
7. React to app lifecycle (didChangeAppLifecycleState)
Responsibility #2 (sync) is entirely independent of #1 (display). They only interact
at the point where a sync completes and the DB is updated.
**Fix:** Create `lib/providers/sync_provider.dart` with `SyncNotifier`:
- State: `SyncStatus` (idle/syncing/error), `lastSyncAt`, `error`
- Methods: `sync()`, `syncFull()`, `syncDelta()`
- On complete: calls `ref.read(catalogProvider.notifier).reload()`
- [x] Create SyncNotifier in sync_provider.dart
- [x] Move sync logic from CatalogNotifier to SyncNotifier
- [x] Wire SyncNotifier.onComplete → CatalogNotifier.reload() (implemented as
      CatalogNotifier.onSyncComplete(), called from SyncNotifier.sync();
      CatalogNotifier.syncFromServer() kept as a thin delegate to
      syncProvider so no call site needed updating — see AGENT_HANDOFF.md)

### E2 — Extract `PosterSyncNotifier` from CatalogNotifier

### E4 — SubscriptionNotifier: add refresh after payment
**File:** `raddflix_flutter/lib/providers/subscription_provider.dart`
**Finding:** After a successful TID submission (`submitTid()`), the subscription status is
not automatically refreshed. The user must reopen the subscription screen to see their

### L10 — `ApiClient.isGuestMode` is a global mutable static
**File:** `raddflix_flutter/lib/core/api/api_client.dart` L56
**Finding:** `static bool isGuestMode = false` is set by `AuthNotifier.continueAsGuest()`.
As a mutable static, it persists across hot restarts in debug mode and could retain a stale
`true` value if the auth flow is interrupted mid-session (e.g. app killed during guest login).
A stuck-`true` value silently bypasses all auth headers and XOR encryption.
**Fix:** This is the same fix as E3 (move globals to Riverpod). Confirm `isGuestMode` is
included when converting `ApiClient` globals to a Riverpod-backed `AuthConfigProvider`.
Reset to `false` as part of the logout flow (same session as A5).
