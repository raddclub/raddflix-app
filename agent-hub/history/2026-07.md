## 2026-07-03 Session B — Player bug fixes

### Bug 1: AI Dubbing returns null (synthesizeToFile path bug)
- **File:** `raddflix_flutter/lib/core/player/subtitle_dubber.dart`
- **Root cause:** `flutter_tts.synthesizeToFile(text, fullPath)` on Android ignores the directory component — it always writes to `getExternalFilesDir(null)` using only the filename. Passing a full tmpDir path meant clips landed in a different location. `File(clipPath).existsSync()` → false → all clips skipped → `clips.isEmpty` → function returned null. Progress animated 0→100% because progress is reported before the file-exists check.
- **Fix:** resolve `ttsDir = await getExternalStorageDirectory()`, pass only the plain filename (e.g. `clip_xxx_0.wav`) to `synthesizeToFile`, then read from `ttsDir.path/$clipName`. Cleanup loop also updated to delete from ttsDir.
- **Commit:** `8829d3d`

### Bug 2: Pinch zoom gray screen
- **File:** `raddflix_flutter/lib/screens/player_screen.dart`
- **Root cause:** `Transform.scale(scale: _pinchScale, child: video)` wrapped a `Video()` widget backed by Android `SurfaceView`. Flutter's `Transform` cannot scale a SurfaceView — the Flutter engine scales the Flutter overlay but the SurfaceView compositor layer remains fixed, showing a gray/blank region.
- **Fix:** Removed `Transform.scale` entirely from `_buildVideoSurface()`. Applied zoom via MPV native property: `_np.setProperty('video-zoom', (math.log(scale)/math.log(2)).toStringAsFixed(4))` in `_onScaleUpdate`; reset to `'0'` in `_onScaleEnd` (snap-back) and the reset-button onTap. MPV `video-zoom` is log₂ scale: 0=1×, 1=2×, -1=0.5×.
- **Commit:** `2918655`

## MPV-Native Player Upgrades 2026-07-03

Goal: push more of the player onto MPV's native engine instead of Dart-side polling/logic — faster, smoother, lighter. Requested by user after a walkthrough of what was/wasn't already MPV-native (speed, zoom, hwdec fallback, dual subs, af= effects were already native; A-B loop enforcement and episode transitions were not).

### 1. Native A-B loop (was: Dart position-listener seek)
- **File:** `player_screen.dart`
- **Before:** the `position` stream listener compared `v >= _abB!` every tick and called `_player.seek(_abA!)` manually — per-tick Duration math + seek call in the hottest listener in the screen, and seek-based looping is never sample-accurate (always at least one frame of drift/stutter at the loop point).
- **After:** added `_syncNativeAbLoop()`, which pushes `_abA`/`_abB` into MPV's own `ab-loop-a` / `ab-loop-b` / `ab-loop-count` properties whenever either point changes (drag handles, clear buttons, `_handleAbRepeat()` cycle). MPV now enforces the loop entirely inside the playback engine — zero Dart overhead per tick, frame-accurate at the boundary. `_playEpisodeAt()` clears both native properties (`'no'`) and resets `_abA/_abB/_abActive` so a loop never carries over to the next episode.
- Dart state (`_abA`/`_abB`/`_abActive`) is kept only for the UI (pin markers, label, "active" tint) — it no longer drives playback.

### 2. Near-gapless episode transitions (background prefetch)
- **File:** `player_screen.dart`
- **Before:** advancing to the next episode (auto-advance or manual "Next") always ran the full remote-link resolution chain (`LocalDb.getShareInfo` → `decodeShareUrl` → `CatalogApi.getShareUrl` → `JazzDriveService.getStreamLink`) after the tap, so there was a visible network-bound gap before the next episode's frame appeared.
- **After:** the `position` listener now fires `_prefetchNextEpisode()` once per episode, ~20s before the episode ends (latched via `_prefetchTriggeredForEp` so it fires exactly once). `_prefetchNextEpisode()` mirrors the same resolution chain but only caches the resolved `streamUrl` + `fileId` — it never touches the player, is a no-op for local/offline episodes (already instant), guards against re-entrancy (`_prefetchInFlight`), and discards its result if the user has navigated away from that target episode by the time it resolves.
- `_openMediaForEpisode()` now has a fast path at its top: if the target episode's `fileId` matches `_prefetchedFileId` and a `_prefetchedStreamUrl` is cached, it skips straight to `_player.open(Media(fastUrl))` — no DB lookup, no share-URL decode, no network round-trip. ## Session 2026-07-06 — BUG-FREE-PLAY-01

### What & why
User reported: playing free OR premium content from a free account always shows
the subscribe/paywall panel — expected for premium, wrong for free content.
Free content COULD be downloaded fine, but could only be *played* after it was
downloaded (never via direct online streaming).

### Root cause
`app.dart`'s `onGenerateRoute` builds the `AppRoutes.player` route with
`PageRouteBuilder(pageBuilder: ...)` but never passed `settings: settings` to
it. `PlayerScreen` doesn't take an `isFree`/`is_free` constructor parameter —
it reads it at runtime via `ModalRoute.of(context)?.settings.arguments` in

`PageRouteBuilder` never forwarded the original `RouteSettings`, that lookup
always returned an empty/default `RouteSettings` with `arguments == null`,
so `is_free` was silently lost on every single online play — `_isFree` was
always computed `false`, `_trackUsage` always `true`, and the Layer-2
subscription gate in `player_screen.dart` fired for free and paid content
alike.

Downloaded content was unaffected because `_playEpisodeImpl`/`_playMovie` in
`show_detail_screen.dart` bypass the player's route-args gate entirely once
`localPath != null` — so downloading (and then playing offline) always
worked, masking the bug and making it look like "download-then-play" was the
only path that worked.

### Fix
Added `settings: settings` to the `PageRouteBuilder` for `AppRoutes.player`
in `app.dart` so the original arguments map (including `is_free`) survives
into `ModalRoute.of(context)?.settings.arguments` inside `PlayerScreen`.
