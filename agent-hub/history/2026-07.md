- **E1** — Read `catalog_provider.dart` in full before touching anything (421 lines). Created

## Session 2026-07-10 — SUBTITLE-SYSTEM-FIXES

### What & why
Continued a prior session's subtitle-system audit that was blocked mid-push
(none of its fixes ever reached `origin/main` — verified via git log before
starting). Re-implemented the fixes from scratch in `player_screen.dart`
(the file with almost all subtitle logic; `_SubtitlePanel`/`_SubtitlePanelState`
around line 6100+).

### Root causes & fixes
- **Gzip decode misuse**: OpenSubtitles serves gzip (RFC 1952), but the code used
  `ZLibDecoder` (RFC 1950 zlib only), which threw and silently fell back to
  writing raw compressed bytes as the `.srt` file. Fixed with `dart:io`'s
  `gzip.decode()` — no new dependency needed.
- **HttpClient leaks**: `_osLogin`, `_fetchOnlineSubtitles`, `_downloadOnlineSubtitle`
  each created an `HttpClient()` and only called `.close()` on the happy path,
  leaking a client (and its connection) on every error/timeout. Moved `client`
  to a nullable var declared before `try` and added `finally { client?.close(); }`
  in all three.
- **Secondary-sid crash**: `track.id!` force-unwrap on the secondary
  (OST/signs) subtitle selection could crash on tracks with a null/non-numeric
  id. Now guards with `id != null && int.tryParse(id) != null` before sending
  to MPV, falling back to `secondary-sid: no` otherwise.
- **Unpersisted sub-delay**: `_adjustSubSync` updated `_subSync` and pushed it
  to MPV but never saved it, so any manual sync offset reset to 0 next time the
  video was opened. Added `pref_sub_sync` to `_savePrefs`/`_loadPrefs`, re-applied
  on load, and call `_savePrefs()` from `_adjustSubSync`.
- **Style desync (PlayerPrefs vs live MPV panel)**: `PlayerSettingsScreen` and
  `QuickSettingsPanel` edit `PlayerPrefs` subtitle style fields, but neither is
  reachable from the live player, and the actual in-player `_SubtitlePanel`
  keeps its own separate `pref_sub_*` SharedPreferences state that is pushed
  straight to MPV. The two stores could show contradictory values. Added an
  `onStyleSynced` callback on `_SubtitlePanel`, invoked from `_saveSubPrefs()`,
  that mirrors font/size/bold/color/background changes into `PlayerPrefs` via
  `playerPrefsProvider` so both stores agree going forward. (Full UI unification
  — e.g. actually rendering a `DualSubtitleOverlay` from `PlayerPrefs` — is a
  larger design decision intentionally deferred; the two dead
  `DualSubtitleOverlay` implementations remain unwired.)
- **Misleading AI-dub error**: `_startDubGeneration` only checked `_currentSubFile`
  (a picked/downloaded SRT), so a user with an embedded/streaming subtitle
  track selected but no file saw "Load an SRT subtitle file first" even though
  subtitles were visibly on. Message now distinguishes the embedded-track case
  and states dubbing needs a downloadable SRT (embedded-track dubbing is not
  implemented — would require extracting text from the MKV track, out of scope
  here).
- **CC icon reflecting existence, not selection**: the sidebar/portrait CC
  button showed "on" whenever any subtitle tracks existed, even with subtitles
  explicitly turned off (`sid: no`). Changed both to check `_selectedSubtitle != null`.
- **OpenSubtitles token re-login every panel open**: `_osToken` was an instance
  field on `_SubtitlePanelState`, which is recreated every time the bottom
  sheet is opened, forcing a fresh login call each time. Made it `static` so it
  survives for the app process lifetime.
- **Preview font family ignored**: `_buildPreview()`'s `TextStyle` didn't set
  `fontFamily`, so the preview always rendered the default font regardless of
  the font selector above it. Added `fontFamily: _mpvFonts[_subFontIdx]`.
  (Alignment was already correctly applied in this codebase version — the
  original audit's alignment claim did not reproduce.)

### Verification
No working `dart`/`flutter` binary was available on `PATH` in this environment
(checked before and after); verification was manual line-by-line diff review,
not `dart analyze`. If a future session has Flutter tooling available, run
`flutter analyze` on this file as a sanity check.

### Not done (explicitly out of scope this session)
- The three dead `PlayerPrefs` fields (`subtitleEncoding`, `subtitleAutoDetect`,
  `rememberSubtitleTrack`) are still unread by player logic — wiring them up
  is a larger feature decision, not a bug fix, and was left alone.
- `_startDubGeneration` still can't dub embedded/streaming tracks (see above).
- The two duplicate/dead `DualSubtitleOverlay` implementations were not removed
  or consolidated — neither is referenced anywhere, so leaving them is safe,
  but a future cleanup pass should pick one (or delete both if truly unused)
  rather than continuing to carry two.

## 2026-07-03 Session B — Player bug fixes

### Bug 1: AI Dubbing returns null (synthesizeToFile path bug)
- **File:** `raddflix_flutter/lib/core/player/subtitle_dubber.dart`
- **Root cause:** `flutter_tts.synthesizeToFile(text, fullPath)` on Android ignores the directory component — it always writes to `getExternalFilesDir(null)` using only the filename. Passing a full tmpDir path meant clips landed in a different location. `File(clipPath).existsSync()` → false → all clips skipped → `clips.isEmpty` → function returned null. Progress animated 0→100% because progress is reported before the file-exists check.
- **Fix:** resolve `ttsDir = await getExternalStorageDirectory()`, pass only the plain filename (e.g. `clip_xxx_0.wav`) to `synthesizeToFile`, then read from `ttsDir.path/$clipName`. Cleanup loop also updated to delete from ttsDir.
- **Commit:** `8829d3d`

### Bug 2: Pinch zoom gray screen
- **File:** `raddflix_flutter/lib/screens/player_screen.dart`
- **Root cause:** `Transform.scale(scale: _pinchScale, child: video)` wrapped a `Video()` widget backed by Android `SurfaceView`. Flutter's `Transform` cannot scale a SurfaceView — the Flutter engine scales the Flutter overlay but the SurfaceView compositor layer remains fixed, showing a gray/blank region.
- **Fix:** Removed `Transform.scale` entirely from `_buildVideoSurface()`. Applied zoom via MPV native property: `_np.setProperty('video-zoom', (math.log(scale)/math.log(2)).toStringAsFixed(4))` in `_onScaleUpdate`; reset to `'0'` in `_onScaleEnd` (snap-back) and the reset-button onTap. MPV `video-zoom` is log₂ scale: 0=1×, 1=2×, -1=0.5×.
- **Commit:** `2918655`

## MPV-Native Player Upgrades 2026-07-03

Goal: push more of the player onto MPV's native engine instead of Dart-side polling/logic — faster, smoother, lighter. Requested by user after a walkthrough of what was/wasn't already MPV-native (speed, zoom, hwdec fallback, dual subs, af= effects were already native; A-B loop enforcement and episode transitions were not).

### 1. Native A-B loop (was: Dart position-listener seek)
- **File:** `player_screen.dart`
- **Before:** the `position` stream listener compared `v >= _abB!` every tick and called `_player.seek(_abA!)` manually — per-tick Duration math + seek call in the hottest listener in the screen, and seek-based looping is never sample-accurate (always at least one frame of drift/stutter at the loop point).
- **After:** added `_syncNativeAbLoop()`, which pushes `_abA`/`_abB` into MPV's own `ab-loop-a` / `ab-loop-b` / `ab-loop-count` properties whenever either point changes (drag handles, clear buttons, `_handleAbRepeat()` cycle). MPV now enforces the loop entirely inside the playback engine — zero Dart overhead per tick, frame-accurate at the boundary. `_playEpisodeAt()` clears both native properties (`'no'`) and resets `_abA/_abB/_abActive` so a loop never carries over to the next episode.
- Dart state (`_abA`/`_abB`/`_abActive`) is kept only for the UI (pin markers, label, "active" tint) — it no longer drives playback.

### 2. Near-gapless episode transitions (background prefetch)
- **File:** `player_screen.dart`
- **Before:** advancing to the next episode (auto-advance or manual "Next") always ran the full remote-link resolution chain (`LocalDb.getShareInfo` → `decodeShareUrl` → `CatalogApi.getShareUrl` → `JazzDriveService.getStreamLink`) after the tap, so there was a visible network-bound gap before the next episode's frame appeared.
- **After:** the `position` listener now fires `_prefetchNextEpisode()` once per episode, ~20s before the episode ends (latched via `_prefetchTriggeredForEp` so it fires exactly once). `_prefetchNextEpisode()` mirrors the same resolution chain but only caches the resolved `streamUrl` + `fileId` — it never touches the player, is a no-op for local/offline episodes (already instant), guards against re-entrancy (`_prefetchInFlight`), and discards its result if the user has navigated away from that target episode by the time it resolves.
- `_openMediaForEpisode()` now has a fast path at its top: if the target episode's `fileId` matches `_prefetchedFileId` and a `_prefetchedStreamUrl` is cached, it skips straight to `_player.open(Media(fastUrl))` — no DB lookup, no share-URL decode, no network round-trip. Falls back to the normal (slower) resolution path transparently if the prefetch hasn't landed yet or failed.
- Net effect: for the common case (user watches an episode through, or close to, its end) the next episode's link is already resolved by the time they'd normally hit "Next" — the perceived transition is close to instant.

### 3. Screenshot with subtitles (long-press)
- **File:** `player_screen.dart`
- `_takeScreenshot()` now takes an optional `withSubtitles` flag, using MPV's native `screenshot subtitles` command (burns in currently rendered subs/overlays) instead of the default `screenshot video` (clean frame). Wired as a long-press on the Screenshot shortcut in the "More" panel (`_ShortcutItem`/`_ShortcutGrid` gained an optional `onLongPress`); the quick-access sidebar shortcut is unchanged (still a clean-frame tap-only shot).

## Session 2026-07-06 — BUG-FREE-PLAY-01

### What & why
User reported: playing free OR premium content from a free account always shows
the subscribe/paywall panel — expected for premium, wrong for free content.
Free content COULD be downloaded fine, but could only be *played* after it was
downloaded (never via direct online streaming).

### Root cause
`app.dart`'s `onGenerateRoute` builds the `AppRoutes.player` route with
`PageRouteBuilder(pageBuilder: ...)` but never passed `settings: settings` to
it. `PlayerScreen` doesn't take an `isFree`/`is_free` constructor parameter —
it reads it at runtime via `ModalRoute.of(context)?.settings.arguments` in

always returned an empty/default `RouteSettings` with `arguments == null`,
so `is_free` was silently lost on every single online play — `_isFree` was
always computed `false`, `_trackUsage` always `true`, and the Layer-2
subscription gate in `player_screen.dart` fired for free and paid content
alike.

Downloaded content was unaffected because `_playEpisodeImpl`/`_playMovie` in
`show_detail_screen.dart` bypass the player's route-args gate entirely once
`localPath != null` — so downloading (and then playing offline) always
worked, masking the bug and making it look like "download-then-play" was the
only path that worked.

### Fix
Added `settings: settings` to the `PageRouteBuilder` for `AppRoutes.player`
in `app.dart` so the original arguments map (including `is_free`) survives
into `ModalRoute.of(context)?.settings.arguments` inside `PlayerScreen`.

## 2026-07-11 — SIMOSA-LOGO-AND-AUDIO-TRACK-FIXES (Session 15)

User supplied the real SIMOSA app icon (a JPEG, uploaded as base64-in-text) and reported: some
videos play with no audio, switching the audio track does nothing, and there's no visual

**Logo:** decoded the upload to `assets/brand/simosa_logo.jpg`, registered `assets/brand/` in

SIMOSA promo row (previously just a 🔥 emoji). Both keep an emoji/letter `errorBuilder` fallback

which corrupts binary content — fixed it to base64-encode images/fonts/media by extension before
uploading via the GitHub blobs API, so future binary-asset pushes don't need a one-off workaround.

**Player bugs — all three traced to real, verifiable causes in `player_screen.dart`:**
1. **Some videos silently have no audio.** The EAC3/DTS/TrueHD software-decoder auto-fallback

   detected an advanced codec — but the project's own documented safety rule (AGENT_HANDOFF.md:
   "hwdec property change only applied when NOT playing — MediaTek/Infinix black-screen
   protection") only guards the *manual* SW-decoder toggle, not this automatic one. Since the
   auto-fallback fires ~1s into playback (i.e. while actively playing), it was violating the same
   rule it's supposed to respect — on affected chipsets this is the likely cause of intermittent
   silent audio on specific files. Fixed by pausing across the property change and resuming after,
   same as the manual path already does.
2. **Switching audio track doesn't apply.** `onTrackSelected` called `_player.setAudioTrack(track)`
   only. Added a direct `_np.setProperty('aid', track.id)` fallback alongside it — mirrors the
   pattern the "Disable" path already used (`_np.setProperty('aid', 'no')`), since relying on the
   native mpv property directly is more reliable across stream types than the media_kit wrapper
   alone.
3. **No indicator of the active track.** The audio panel's `RadioListTile`s compared
   `AudioTrack` objects with `==` to decide which dot to light up. media_kit can emit fresh track
   list instances across stream updates, so this comparison was unreliable regardless of whether
   the *same* track was genuinely selected. Rewrote the panel to resolve a `selectedIdx` by
   matching `track.id` once, then drive both the disable option and the track list off that
   `int` — immune to instance-identity issues.

### G1 — go_router migration: scoped, deliberately not started
Initial explorer subagent estimated 250+ Navigator call sites; a precise grep for the calls that
actually break under go_router (`pushNamed`/`pushReplacementNamed`/`pushNamedAndRemoveUntil`)
found the real number is ~75 across 25 files — the rest were `Navigator.pop`/local
`Navigator.push(MaterialPageRoute)` calls that don't need to change.
The real blocker: `player_screen.dart` reads `ModalRoute.of(context)?.settings.arguments`
directly in 3 places (~L796, ~L865, ~L1341), not just via constructor params — one of these
is the `is_free` flag that BUG-FREE-PLAY-01 already broke once (free content got charged
because a `PageRouteBuilder` didn't forward `settings:`). go_router's `extra` does not populate
`ModalRoute.settings.arguments`, so this needs deliberate rework — and this repo's CI only runs
`flutter build apk` (compiles, never executes navigation/playback logic), so a regression here
would ship silently with a green build.
Asked the user directly with this risk laid out; they chose to leave G1 undone rather than
risk a silent monetization-gating regression with no way to verify it pre-merge. Documented the
scoped call-site list and the exact ModalRoute read sites in TEN_POINT_PLAN.md's G1 section so
the next session (ideally paired with real-device/manual QA) can pick it up without re-deriving
the investigation.
